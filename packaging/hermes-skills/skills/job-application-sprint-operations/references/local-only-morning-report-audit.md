# Local-only morning report and stop audit

Use when the current task explicitly authorizes reporting and schedule pauses but prohibits browser, CDP, restart, account access, applications and recruiter messages.

1. Load the operator and sprint skills, plus hermes-agent for schedule controls. Read the campaign manifest, ledger and deadline handoff. List profile-scoped jobs, pause only the requested existing owner/scout jobs and read their exact states back. Distinguish paused schedules from completed or still-running executions. Do not create jobs, extend deadlines or claim pause canceled a send.
2. Parse every nonempty JSONL line with Python and dedupe on known end client or direct employer. Preserve reported row totals separately from evidence-qualified counts. Exclude explicit delivery-failure, withdrawal, duplicate and quality-incident statuses. Compare the canonical counter with its baseline only as a cross-check, never as the campaign count source.
3. Resolve documented field aliases and relative evidence paths. For each counted company inspect saved actual submission evidence, immediate approved-resume receipt, form/location QA and exact Teal record. Verify dates at the provider's saved precision. Require both the selected status relationship ID and the matching included Status object's attributes.name. A relationship stub has type/id but no attributes and must not shadow the included object during recursive extraction.
4. For email, match the exact saved provider message ID, SENT label, provider timestamp, body and attachment evidence. If a compact summary omits labels, recover them from a saved full readback with the same exact message ID. Hash the saved actual downloaded Sent attachment, not merely the selected local file. For native ATS, require saved normal submit/response/confirmation evidence, guarded selected-file proof and exact role; do not mistake a reachable receipt URL for a submission. State explicitly when remote stored-file download was unavailable.
5. Read all relevant tick results, newer canonical sections and saved bounce associations. Prefer later explicit failure or withdrawal evidence over earlier positive summaries. Do not reopen accounts to refresh evidence when current instructions prohibit account access. State that the report audits saved evidence, not a new live account check.
6. Scope outreach totals explicitly. For counted applications, separate application emails from additional recruiter emails, exact LinkedIn Sent/Pending requests, queued contact actions and unsuccessful contact research. Do not silently mix a withdrawn company's historical invitation or a failed application's still-valid invitation into counted-company follow-up totals. Require exact profile URL and recipient-specific Pending/withdraw control, or exact Sent/Withdraw recipient card. Match the actual email body with the canonical outreach row after normalizing CRLF only.
7. Compare the complete CSV with a read-only SQLite snapshot using a multiset of full normalized row tuples. Normalize SQL NULL to CSV empty values. Do not key this comparison solely by event_id: legacy null IDs are legal in some SQLite schemas and dictionary collapse can create a false mismatch despite equal complete exports. Preserve multiplicity and compare all columns.
8. Save a local audit artifact listing every counted company, resolved evidence paths, selected status/date, hash checks, exclusions, channel totals, outreach totals and schedule readback. Keep unresolved schema issues explicitly non-counted until recovered from existing evidence. Save a concise human-readable report with target/shortfall, real submission-platform spread, outstanding human facts/consents and evidence folder. Do not send messages directly when the scheduler delivers the final response.
