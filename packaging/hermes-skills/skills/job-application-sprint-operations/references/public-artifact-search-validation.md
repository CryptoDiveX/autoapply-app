# Validate public-scout local artifact discovery

1. Validate returned file-search basenames against the requested employer pattern before accepting a match. A glob search can return unrelated hidden dependency paths; neither those results nor an empty filtered projection establishes employer history. Inspect content-search schema too: `matches_text` plus `total_count` can replace `matches`. An absent guessed array is not zero history. Preserve the failed projection, read actual path-grouped matches and recover the allowlist before dispatch.
2. Recover suspicious results with a bounded read-only local filesystem walk that prunes node_modules, .git and virtual-environment directories. Match exact employer aliases against actual basenames, retain the matching paths, then inspect exact role/source lifecycle evidence.
3. Preserve the faulty result and recovered index separately. A parser or discovery-tool mismatch permits only read-only recovery, never candidate replay, a new application count or an unsupported fresh-employer claim.
4. Inspect the actual historical artifact-name matches before exact-role fetching and appending, not merely save their paths. Earlier exact-role triage can be absent from canonical headings, prospect JSONL and the current queue. A negative text search alone is inconclusive.
5. If an unchanged prior deferral is discovered after append, retain immutable prospect bytes, annotate that exact research row and publish corrected fresh-supply versus overlap counts under established shared locks. Preserve any newer scout handoff and all owner fields. Never replay research or candidate actions to repair attribution.

8. Store a disposition-read decision with each exact URL admitted to a browser-inspection allowlist. A search returning prior role matches is not clearance: read the original decision first, classify unchanged versus genuinely changed evidence, and admit only the cleared read-only stage. Assert this decision immediately inside each dispatch, not only before a loop. Searching only filenames containing result can miss scout disposition files; check the exact posting ID across the relevant JSON artifacts before treating it as fresh. If a match appears after read-only inspection, preserve the incident, remove the unchanged URL from the allowlist and recover logging only.

9. Match exact posting IDs within provider routes before authorizing a shorter URL, not as arbitrary substrings across unrelated IDs. Kula routes such as `/account/52802` and `/account/52802-title-slug` identify the same posting. Bind account plus numeric posting ID, then inspect the existing lifecycle row even when the employer name is absent from the canonical log. A later canonical redirect permits read-only incident recovery, not another candidate attempt.
11. Resolve spaced versus concatenated employer aliases through the exact original posting URL in the full current Teal inventory and historical artifact contents before treating a negative company-name search as fresh supply. A discovery name such as Morpheus One can correspond to an existing MorpheusOne Applied record. Preserve both observed spellings and the exact URL; do not resend, rename the tracker or claim a new quality audit to repair alias discovery.

10. Inspect root current-inventory responses locally before browser dispatch when broad search repeatedly returns worldwide mirrors. A feed's salary headline does not override performance-only body compensation, and an all-remote culture does not override an exact role's US/Canada home-location rule. Preserve those distinctions without generating speculative Teal records or increasing application-attempt counts.

12. Inspect imported prefilter implementations before relying on their allowlists. A helper that checks only the canonical log, current Teal and shared queue has incomplete coverage: require a retained exact-posting-ID search across prior scout disposition and lifecycle artifacts, read each matching original decision and bind the allowed inspection stage before dispatch. Do not treat a positive helper allowlist as freshness when it omits those sources. A helper using unbounded `re.finditer(re.escape(alias), log)` can reject Agora solely because Binagora is present. Preserve that receipt, rerun the exact alias with token boundaries plus full Teal/source/queue checks, and admit only the recovered read-only stage under a new evidence prefix. Do not patch historical receipts, clear genuine lifecycle matches, reopen unchanged deferred roles or repeat candidate actions to repair a substring collision.

13. Search the exact observed posting URL or posting ID across historical scout decision-file contents before each exact-role GET, independently of employer-basename matching. Also search compact employer/domain aliases before treating a new job-board mirror as fresh: spaced company-name searches and a previously unseen mirror slug can both miss an existing native ATS deferral. Derive aliases only from observed employer names, domains and current public links. A newly posted mirror timestamp does not reopen the unchanged native role; recover its original decision read-only and retain any accidental mirror inspection as overlap. Legal-name basenames can miss compact aliases such as Housecall for Housecall Pro or product aliases such as NovoIoT for Novo AI GmbH. Bind the original disposition and keep an unchanged source outside the fetch allowlist; a later alias recovery earns zero fresh supply and permits local logging only. Retain the exact-URL audit alongside the alias audit so a legal-name-only negative cannot silently authorize a repeat.

14. After detecting that an inherited prefilter omits prior scout decisions, fail that helper's prefilter closed and require a separate exact-URL disposition-clearance record inside its actual inspection dispatch. Exercise a known unchanged deferred URL and verify rejection occurs before target creation. Merely logging incomplete coverage while leaving the old allowlist callable permits the same accidental read-only recycling on later ticks. Preserve prior observations and recover only local helper/verification stages, never candidate actions.

15. Batch employer aliases and exact posting IDs into one bounded content search, then read the exact containing dispositions. Do not recursively read every multi-megabyte artifact separately for each employer: repeated queue snapshots and full tracker exports can time out before retaining a useful prefilter. After a timeout, preserve it and recover only exact-source searches, the current parsed queue and relevant log sections. Missing partial output is not a negative duplicate check.

16. If a multi-company audit projection is character-truncated, inspect the complete retained per-employer result before constructing its fetch allowlist. Omitted console lines do not mean zero matches. Resolve observed brand/domain aliases and read every retained matching disposition; a different careers query value does not make an unchanged employer inventory or country restriction fresh. Preserve any accidental read-only repeat as overlap and recover only audit attribution, never append another unchanged lead.

17. Treat a search-tool regex error as failed discovery, never as a negative history result. The default ripgrep engine can reject lookaround; recover with supported word boundaries and inspect exact employer domains and source URLs. For an employer name that is also a common verb or technical noun, such as Interfacing or Parser, unrelated role prose, helper filenames and dependency files are not company matches. Search parsed identity fields and exact employer domains before projecting whole prospect objects: the word parser in audit paths can match many unrelated employers even with token boundaries. Preserve the failed query and rejected lexical hits, then bind the exact-domain recovery to the same preflight without reopening prior candidate actions.

18. Treat technical-looking employer names such as 100ms as ambiguous even with word boundaries: saved browser and request audits can contain the same literal as a wait duration. Require the exact employer domain, observed ATS account or parsed company identity before attributing those hits to candidate history. Preserve the rejected latency-only projection and recover only read-only filtering, never candidate actions.

19. Bind repeated-title ATS links to the smallest current inventory card or list-item ancestor containing both the exact href and its location before selecting a role. Never zip separately collected titles, links and page-text location lines by index: a missing row or repeated card can shift a Multiple Countries label onto a Brazil-only URL. Preserve the exact row-to-URL projection, then read the selected role's own geography and requirements. A read-only mismatch permits attribution recovery only, never promotion or candidate entry based on the neighboring card.

20. Compare employer domains as parsed URL hostnames, allowing only exact host equality or a dot-delimited subdomain. Substring matching can attribute careers.singlegrain.com to grain.com and falsely suppress a different employer. Preserve the rejected projection, test exact hosts, valid subdomains, unrelated prefixed hosts and deceptive suffixes, then rerun only the read-only identity filter. A shared word such as Grain in Single Grain still needs containing-record attribution even with token boundaries; do not clear real source matches or replay candidate actions to repair the helper.
