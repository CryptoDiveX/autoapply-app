# Overnight application execution

Use this recipe for numeric additional-application targets, continuous overnight work and a morning result handoff. Standing document, browser, communication and safety rules remain in the two governing job skills.

## 1. Freeze the campaign before launching

Create a run folder and a compact manifest with:

- Requested additional target, start time, stated deadline and report timezone.
- Baseline log count and the actual company set/evidence used to establish it.
- Numerical milestone, computed with tools, plus an explicit note if the historical log was not freshly artifact-audited.
- Paths for the new verified-submission ledger, append-only prospect queue and tick results.
- Current approved resume path/hash and exact-byte gate.
- Browser owner, platform exclusions, no-retry companies/addresses and outreach quota policy.
- Actual submission/scout/report job IDs returned by tools, never guessed IDs.

Preserve prior ledgers. For a continuation, keep the existing target; for an explicit fresh additional request, freeze a new start and baseline and announce the new scope. A late historical completion can change the global counter without belonging to the new campaign.

When a fresh nightly target overlays an already-running continuous campaign, preserve its sole browser owner and execution ledger. Add a separate manifest with an explicit actual-submission cutoff, prior-employer snapshot, new-company reference ledger and independently computed nightly count. Announce whether the number is new applications or remaining progress before dispatch. Persist the new objective in both owner/scout prompts and their active shared brief/notepad; editing future prompts is not proof an in-flight worker adopted it. Previously authorized in-flight submissions after the cutoff may qualify only after full verification. Keep earlier statuses, global milestones and new-night progress separate. Check current bounce/withdrawal evidence outside the source ledger too, because an older verified_submitted row can remain after a later failure was recorded elsewhere. A morning progress report must not silently stop a campaign that remains continuously authorized.

## 2. Divide work without competing browser owners

During non-interference or approved-document recovery, use:

- **One submission owner:** live form triage, guarded resume upload, truthful per-question answers, submit, external verification, exact Teal readback and bounded recruiter follow-up.
- **Read-only source scouts:** public HTTP/search and local dedupe only. Append prospective roles with company/end client, role, official posting/apply URLs, platform, location, source evidence and eligibility caveats. Never drive CDP, touch authenticated Teal, send outreach or mark prospects Applied.
- **One morning reporter:** audit saved evidence, stop future schedules at the announced endpoint and report actual verified totals and shortfall. No new submissions or recruiter sends from the reporter.

Scouts keep the queue supplied across ATS families while the owner protects one persistent browser session. The owner must still live-check a discovered role; search results can be stale and scouts cannot certify the final form.

## 3. Launch durable bounded work now

List existing jobs, update/reuse an eligible recurring owner, and read back its configuration. Put the complete brief in a durable prompt file and explicitly point each job to it. Use short no-continuity ticks rather than injecting growing prior outputs.

A practical starting cadence is a submission tick every five minutes and a read-only scout every twenty minutes, provided the scheduler skips overlapping owner executions. Give each owner tick a small batch, such as one to three verified submissions and several alternative targets over roughly fifteen to twenty minutes. A tick interval is not a promise of that submission rate.

Fire owner and scout immediately. Save returned async run handles, then continue independent work or end the parent turn so completions can arrive. Do not poll or wait on cron/delegated transcripts. If firing is skipped because the owner is already running, report that distinction and do read-only work instead of competing for its tabs.

Pausing prevents future scheduled runs, not necessarily already-running work. Prompt edits govern subsequent runs, not an existing worker's context. Inspect in-flight activity separately before claiming it stopped or adopted a new policy.

## 4. Make every outbound step fail closed

Select the exact approved PDF or an unchanged renamed copy. Call the approved resume guard immediately inside the send/upload path with `subprocess.run(..., check=True)`, save the receipt and abort that operation on a failed check. Do not execute legacy generator/senders. Personalize only candidate text in approved-document mode using the scoped copywriting model and canon QA.

Before submit, verify visible answers, normalized hidden location, units and legal facts. Continue to a different target for ordinary blockers; preserve human-action blockers without bypassing them. After submit, require external success plus exact Teal Applied/status/date/readable-note readback before adding a company to the ledger.

After each verified application, attempt bounded professional-source outreach. Prefer LinkedIn notes, use the authorized no-note connection fallback for exhausted note allowance, verify exact-profile Pending and avoid duplicate invites. Email/WhatsApp/SMS require a current publicly published professional address/number and a safe established sending path. Log sent, blocked and queued actions, not fabricated successes.

## 5. Preserve browser and power state

Keep at most three working pages and reuse one Teal page. Close only completed/dead owned tabs after evidence, not the Cloak process or last user window. A user request to open the browser does not permit unrestricted foreground automation afterward.

On macOS, compute the seconds remaining to the announced deadline using actual time and an explicit timezone. Run `/usr/bin/caffeinate -i -t <remaining-seconds>` as a tracked background process for that authorized interval, and verify the process exists. Allow display sleep; do not add display-awake flags unless requested. Remind Vasya to keep the Mac powered on with its lid open. This prevents idle sleep, not manual shutdown or lid closure, and does not guarantee uninterrupted network/model availability.

## 6. Stop and report actual outcomes

Check target/deadline before each new target and immediately before an irreversible send. At the endpoint, pause the actual listed owner/scout jobs and save final state; do not claim pausing canceled an already-running submit.

If promising a morning report, create a real one-shot reporting job for the announced timezone and verify its persisted schedule and destination. Keep routine overnight results and engine errors local. Morning output is concise English with emoji headers and numbered results, not raw errors/configuration/tool traces.

Audit the campaign ledger with code:

1. Deduplicate direct employers or known end clients.
2. Require submission proof, approved-file receipt, Teal readback and claim/form QA for each counted entry.
3. Remove later bounces, duplicates and document/legal/location incidents.
4. Count outreach from channel readbacks, separately from application totals.
5. Report verified additional count, platform spread, sent/queued outreach, human-action blockers and any shortfall.

Never substitute historical log-count subtraction, a scheduled run, a prepared document or a clicked button for verified campaign progress. Save enough evidence to resume safely without replaying any uncertain submission.
