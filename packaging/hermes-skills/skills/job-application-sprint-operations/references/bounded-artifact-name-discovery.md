# Bounded artifact-name discovery

1. Screen small employer batches with current cached full tracker inventory, canonical log and every shared queue bucket, then exact word/domain or posting-ID content queries and narrow filename globs.
2. Never request the entire application tree with a six-figure file-search limit for a small candidate batch. Enumeration and returning a huge result can consume several minutes before any public role inspection.
3. Reuse an existing current local filename index when available. Resolve only exact matching employer or source dispositions before dispatch, preserving uncertain outbound-state protections.
4. Treat search brands embedded in ordinary words as false positives unless exact employer/domain evidence corroborates them. For example, Scribe must not match prescribed. Save the rejected projection and recover filtering only, without repeating candidate actions.
5. When recursively inspecting shared-queue employer matches, distinguish actual lifecycle rows from nested country and recipient evidence. Apply status assertions only to records that contain the observed lifecycle status field; a country-gate dictionary can repeat the company name without representing a prior application. Preserve the exact JSON path and recover filtering only after a nesting assertion fails, without replaying candidate actions.
6. Validate returned filename-search paths against the requested basename glob before using them as lifecycle evidence. A broad tree search can return unrelated node_modules directories or fail with a transient process error. Reject those paths, then recover with a bounded exact-domain or posting-ID content query and an explicit file_glob such as *.json. An unrelated directory result is neither an employer match nor proof that no matching artifact exists.
