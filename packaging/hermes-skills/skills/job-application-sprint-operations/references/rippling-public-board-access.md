# Rippling public board access

When an employer-published Rippling board redirects to `https://app.rippling.com/apps_sso_direct/RipplingATS` and shows Sign in, preserve the exact official link, final URL, retrieval timestamp and visible shell as an unresolved public-inventory access gate. An HTTP200 login page does not establish a working public application, an empty board or closure of an independently advertised role.

Inspect an employer careers page's observed Rippling iframe when the parent contains no job cards. A published `/embed/<employer>/jobs` route can render a genuine public inventory without SSO even when another Rippling entry point redirects to login. Preserve the exact parent-to-iframe link chain, current role cards and exact native role URL; an empty parent text extraction is not an empty employer board. Do not construct an embed or role URL, and apply the exact role's work-rights and geography requirements before candidate entry.

Keep public scouts unauthenticated. Do not sign in, create an account, invoke SSO, enter candidate data or substitute an unsolicited general-inbox application. If a separately observed current employer-controlled native route is available, inspect it read-only under the normal exact-role lifecycle guard. Otherwise retain the shortfall and leave access review to the sole authorized application owner.

Keep same-name employers separate by exact official domain. A search result for a healthcare product does not establish a vacancy at an unrelated revenue-enablement company using the same short brand.
