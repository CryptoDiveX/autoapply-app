# Public extraction and inventory cross-checks

0. Inspect the visible verification controls beside Apply before clicking it. A native ALTCHA checkbox labeled Verifying and Protected by ALTCHA is a visible challenge even when the full job description has already loaded. Preserve its label, requiredness and exact role URL without security values; do not toggle it, run its proof-of-work, invoke a solver or spend on candidate copy. Retain the role as current but challenge-blocked, not closed, and continue unrelated eligible alternatives. Search-indexed role text and a visible Apply button alone do not establish form readiness.

1. Compare positive extraction with current public HTML before recovering a stale mirror or an apparently empty careers section. Extraction can omit an exact Job Expired or Just Join IT Offer expired notice while preserving the full role, an Apply-like template and a stale days-left date, or omit named-role cards that remain in official HTML. Preserve both observations and follow the official observed native board. Keep an expired mirror's exact title separate from current differently titled native vacancies; a current sibling does not revive the original role.
2. Count unique exact job-detail links separately from duplicate View details and Apply links. An Instructure public Ashby inventory HTTP403 does not erase a complete current official HTML inventory. Preserve the failed API response and the successful independently parsed HTML inventory separately.
3. Treat an official linked native board explicitly saying no open positions as stronger current evidence than an expired mirror. Keep the mirror's exact closure separate from the board's current status, and do not substitute a general intake or unsolicited email.
4. Keep these additional native-route procedures available: [DOSS Astro inventory](doss-astro-inventory.md) and [TopCSJobs native routes](topcs-public-native-route.md).
4a. Inspect the settled native audience banner before treating a search-indexed public posting as externally available. An Infor page can expose a complete description, Fully remote metadata and Apply Now controls while explicitly stating it is for internal candidates only. Preserve that exact banner and role-specific UK or travel scope; do not enter candidate data, assume external eligibility or substitute another inbox. Resolve an existing exact Archived tracker and its attributes.note before reopening the role, even when canonical-log headings omit the employer.
5. Inspect the current official footer hiring link even when extraction preserves an older no-openings section. Harvest can hand careers to a Bending Spoons board through an observed short link; save that exact redirect chain and evaluate the current recruiting employer and exact role instead of declaring Harvest closed or assuming the parent inherits worldwide hiring.
6. Inspect native details/summary controls when an FAQ question has no button. Bind the visible exact question to its own details answer, or preserve current official HTML and structured public metadata read-only. Keep remote-country permission separate from visa-sponsorship countries: Georgia with enablesRemoteWork false and eligibleForVisaSponsorship true supports potential relocation sponsorship, not remote work from Batumi. Do not change residence or substitute another country to pass the gate.
7. Cross-check an unexpectedly empty live anchor projection against the current official HTML before declaring a hiring route absent. Hydrated or embedded product demos can leave visible navigation text while the snapshot misses server-rendered hrefs. Retain the exact published Company or About link and follow it read-only; demo Send and Submit controls are not application controls. If an officially linked employer ATS subdomain redirects to the ATS vendor's marketing homepage, preserve both the original observed employer link and final destination, classify that route unavailable rather than company-wide hiring closure, and never substitute the vendor's careers page or a general inbox.
