# Keka public careers inventory

1. GET the exact employer-linked careers URL. A shell can contain an observed `fetch('/ats/documents/<identifier>/careerportal/<asset>.html')`. Follow that exact public GET, never guess the identifier.
2. Read the returned public `window.khConfig` domain and identifier plus its exact `careers/api/embedjobs/js/<identifier>` script. Inspect only public careers/listing behavior offline, never execute it. `text/js` is JavaScript even without a .js suffix. Invalidate any HTML-derived text/links produced by a generic helper and retain the raw module.
3. When the actual module constructs `khConfig.domain + api/embedjobs/${portalName}/active/ + khConfig.identifier`, use the observed portalName or its published default. Fetch only that read-only inventory. Do not invoke candidate, upload or application routes.
4. Preserve full source and retrieval URL/status/time. Count actual JSON rows, project title, ID, published date, experience and jobLocations countryName/countryCode. Descriptions can contain very large base64 images: extract their text offline rather than printing the entire response.
5. A generic company careers page advertising Strategy, Operations or global client work is not a current product/delivery vacancy. Report an inventory with engineering-only roles accurately rather than calling the board empty. A location named Remote with countryCode IN is not worldwide eligibility.
6. Keep public inventory proof separate from company identity/HQ, current role geography, candidate-facing form gates and sole-owner live readiness. Scouts never enter candidate data or claim submission.
7. A visible Keka footer with no job cards does not establish an empty board. Inspect the current active window.khConfig and observed deferred embedjobs script, not an older commented-out tenant or custom widget proxy. The current native inventory can contain several paid roles even while the employer wrapper displays only Powered by Keka. Decode all rows and preserve their location country codes plus full work-mode wording; Head Office Pune and Work from Office are not global eligibility. Never manually initialize the widget or repurpose a general hiring inbox to bypass that geography.
