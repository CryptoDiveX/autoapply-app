# Greenhouse response and upload audit

1. Key response bodies by exact Network.requestId and restrict verification to the observed final POST. Several responses can share the job URL, including navigation resources.
2. Retrieve the matching POST body as soon as its response arrives in the same persistent CDP session. Normal navigation can evict the resource before a later read. Flush network events in finally and use immutable per-request filenames.
3. If the response body is unavailable after genuine native confirmation, preserve the correlated HTTP status, exact candidate request, committed file reference and normal confirmation. Label the missing body explicitly. Never resubmit to improve evidence or fix a verifier collision.
4. Whitelist candidate fields and correlation metadata before serialization. Exclude cookies, authorization headers, security/challenge tokens and device fingerprints.
5. For retained upload components, save only selected filename and committed storage URL/key. Never serialize the whole uploadManager or signed formFields: these can contain storage policies, credentials and signatures. Private overbroad evidence must be access-restricted and replaced in routine audit output by a sanitized derivative.
6. Distinguish actual upload response capture from ResourceTiming evidence. A same-page PerformanceResourceTiming responseStatus 201 corroborates an upload but is not a downloaded attachment hash. Bind the exact committed reference to the final normal application POST, retain the immediate approved-file guard, and explicitly label unavailable private storage bytes.
7. Read back exact Teal status/date and separately rendered cover paragraphs. HTML can preserve literal linefeeds while rendering one paragraph. Repair only the tracker paragraph serialization, preserve candidate prose and original application date, then rerun only read-only verification.
8. When a successful Greenhouse upload replaces its file input with a filename preview, recover only read-only committed-state verification. Start at the exact preview text, inspect its observed React fiber ancestors and locate the resume field by its actual name rather than a minified component name or fixed hook index. Whitelist the retained resume name/storage URL and exact candidate fields, then bind that storage URL to the final normal application POST. DOM-only __reactProps scans can miss component props entirely. Never serialize the whole upload manager or hook tree, and never reupload because the original input disappeared. Compare normalized canon phone digits locally before interpreting masked tool output as a defect.
9. Inspect the retained resume field's observed keys before assuming a nested value property. Greenhouse can store the committed resume directly as {name, url}; reading only resume.value falsely reports an empty upload. Preserve the exact safe name/url pair, successful storage response and matching job_application.resume_url in the final normal POST. Keep the phone Country dial-code selector separate from current residence, and verify the full normalized phone in current form state. Missing final response bytes after normal confirmation are a read-only audit limitation, not permission to upload or submit again.
10. Exercise the final-request sanitizer against the current native custom-question serialization before relying on its coverage. A projector that preserves contact fields, cover text and resume_url can still omit salary, residence and optional-consent answers stored under another container. Whitelist only the exact observed public question IDs and candidate values, excluding all security fields, and retain that sanitized projection before navigation. After a genuine submission, recover only read-only evidence and distinguish exact pre-submit DOM/committed-state answers from unavailable final serialized or remote answer readback. Never repeat Submit or claim the omitted answers were externally read back merely because contacts and resume binding were captured.
