# CDP navigation context and partial-review recovery

1. During bounded same-target navigation readiness, tolerate only the transient `Cannot find default execution context` error. Require a non-null body, departure from about:blank and the intended identity before snapshotting; document readyState alone is insufficient.
2. Persist the owned target ID before waiting and arm exact-target cleanup before a readback can fail. Never close original user, tracker or review tabs to repair a new owned readback.
3. Inspect immutable receipts after a partial helper fails. If tracker Notes, monitor rows or canonical outreach already have positive exact readbacks, recover only missing UI verification and local queue handoff under new filenames. Do not rerun the combined logger, create duplicate rows or replay any external action.
4. Treat an observed LinkedIn Message destination displaying Something went wrong with no editor as unresolved history, not empty history or send failure. Record zero sent messages and no intent when neither exists. Retain the person-keyed hold instead of spending copy tokens or repeatedly reopening the unchanged route.
5. A responsive browser endpoint with an unresponsive page renderer is not evidence that the browser exited. Preserve the process, original tracker and user pages. Attempt bounded read-only recovery only; if it fails, retain exact successful API proof and explicitly mark rendered Notes verification pending.
6. If the exact tracker page stalls after read-only navigation and there is no in-flight candidate action, submission or tracker write, one bounded `Page.stopLoading` followed by a short `Runtime.evaluate` probe can recover the existing renderer without restarting Cloak. Require the retained exact page identity, then independently retry only the unfinished read-only inventory or rendered-Notes verification under new evidence names. Do not replay initialization receipts, successful Notes writes, outreach logs or sends. Never stop loading on a page with an uncertain outbound action.
