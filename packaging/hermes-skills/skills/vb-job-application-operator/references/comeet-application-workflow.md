# Comeet application verification

1. Follow the official company careers link into its observed Comeet board. Static extraction can expose unrendered Angular placeholders and a template saying no positions. That is not a live closed-job decision. Use the current browser board and exact rendered role. Distinguish same-title roles by position UID, full description and working location.
2. If a Framer openings page has no visible jobs, inspect its srcdoc iframe for an official Comeet integration, then follow that observed company board. Do not infer that a blank embed means no vacancies.
3. Open the exact observed Apply button normally. The form may live in a cross-origin iframe exposed as a separate CDP target. Enumerate that target, read its labels, mandatory state, dropdown options, privacy text and visible challenges. Never guess a country, legal answer or dropdown value.
4. Commit text through native input/change/blur events. When Angular scope debugging is disabled, scope() may return undefined even though the form works. Read angular.element(input).controller('ngModel').$modelValue instead. Compare each visible answer with its normalized model, especially phone and exact free-text screening answers.
5. Treat the phone country selector as a telephone calling code, not residence. Verify its observed country option and normalized international phone. Keep current residence explicit in the citizenship/physical-work question and cover note.
6. Run the approved resume guard with check=True immediately before DOM.setFileInputFiles. Keep getDocument, querySelector and setFileInputFiles on the same CDP session. Read the selected File model name and size as well as visible filename. This proves selection, not remotely downloaded bytes.
7. Use the personal-note field for job-specific cover copy when cover-file upload is optional and no approved cover PDF is available. Verify actual line breaks. A valid JSON string can still contain literal backslash-n text; deterministic newline decoding is formatting, not permission to rewrite candidate claims.
8. A privacy-policy review link alone is different from a required legal acceptance. Inspect actual controls. A zero-size invisible reCAPTCHA resource is not a visible challenge; stop if a visible challenge or human-check appears. Never invoke a solver or manufacture its response.
9. Save exact pre-submit visible/model values, selected English level, phone normalization, File name/size, hidden inputs and privacy/challenge state. Submit once through the normal UI. Require the actual form to show an explicit success such as Your application has been submitted. Never navigate to a guessed receipt or retry to obtain prettier evidence.
10. Fetch a matching employer receipt email when available and save its exact sender, recipient, role subject and provider timestamp. Preserve the original ATS submit time separately. Complete exact Teal Applied/date and readable Notes, outreach SQLite/full CSV and canonical log before ledger count.
11. For employer duplicate searches, scope numeric job IDs to their exact URL patterns. A bare digit substring can match an unrelated phone and falsely block a clean company. Employer name, domain, known aliases and actual submitted evidence remain the governing guard.
