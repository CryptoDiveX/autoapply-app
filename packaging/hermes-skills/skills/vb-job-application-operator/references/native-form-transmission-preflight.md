## Framer native careers forms

1. Inspect the current form ancestor's public action and native onSubmit handler read-only. A real Framer form can keep action on an ancestor React prop while the HTML form action attribute is null. Require the exact observed forms/v1/forms/<id>/submit route, normal candidate FormData and meaningful transmission before entry; never invoke the handler for inspection.

Bind response bodies by exact requestId. A successful native POST can return JSON null without an application ID; require normal settled visible success as corroboration.
3. Parse the original multipart candidate parts while the submitting CDP session is alive. Use the body's actual boundary, normalize CRLF only for candidate-text comparison, retain whitelisted candidate values and Role, and exclude security data. A JSON-only projector can return empty fields for valid multipart; this is an audit limitation, not evidence that the employer received no candidate data. Never replay a submit or close the session before preserving its available request data.
4. Recheck the exact original target after the normal action settles. Framer can replace the form with a success sibling, so queries scoped only to form p or form button can miss a real visible Thanks for your application! notice. Verify the exact visible leaf text and screenshot after the action. Initial hidden success/error variants inside a button are implementation evidence only.
5. For a genuine native work-website and narrative-answer route with no resume picker, use the exact canon agency work website truthfully, not an invented hosted resume or formal portfolio. Preserve native receipt and Teal Applied/date/readable answers, but record no PDF delivery, no applicable file-guard operation and zero strict approved-file campaign credit. Keep unavailable transmitted-body evidence explicit and never send an unsolicited corrective attachment to manufacture file credit.
6. Replace stale preparation wording in tracker Notes after success while preserving the actual application date and selected status. Verify description text after documented HTML-entity decoding, but keep Notes and candidate-answer comparisons exact. A read-only verifier or final console-print failure does not authorize repeating a completed tracker mutation or native submission.

6. Keep the original network-audit session alive through bounded native AJAX completion, not merely a fixed seven-second post-click delay. Persist the actual final multipart immediately, then pump until that request's response/loading-finished state and ordinary success or error settle. 7. Correlate resource-timing evidence with the exact final request timestamp and initiator, not just its endpoint URL. Label each unavailable item explicitly.
