# JobDiva linked recruiter resume responses

Use for an explicitly user-authorized reply to an incoming recruiter email containing a JobOpportunityForYou/JobDiva resume-response link.

1. Resolve the exact incoming thread, sender, role, location and observed response link. Treat the first emailmerge_response.jsp GET as potentially registering interest, not harmless public research. Do not open a personalized response link until that action is authorized. Preserve its identifiers and encoding exactly; do not replace it with a generic portal or reconstruct a broken-looking redirect.
2. Refresh the original thread, Sent search, Teal and outreach before either channel. If the user explicitly requests linked upload and same-thread email, do both, but count the vacancy once. Previously sent intent or success permits verification/log recovery only, never automatic repeats.
3. The normal acknowledgment can offer an updated resume and state that it will be available for other matching jobs received by the recruiter. Retain that notice. Distinguish ordinary internal recruiter processing from a new checkbox, public-profile exposure change, account creation or unrelated permission request; stop for genuinely new permissions.
4. Guard the exact selected PDF immediately before DOM.setFileInputFiles, compute its browser File SHA-256/name/size, and click the observed Upload control once through normal native UI. The control may be a span with onclick rather than an HTML button. Do not invoke the upload function directly or synthesize its request.
5. Preserve intent before Upload and save network metadata in a finally path. Navigation can temporarily destroy document.body immediately after a successful upload. Use document.body?.innerText and bounded read-only readiness waits. A readback TypeError is not an upload failure or permission to click again.
6. On interrupted readback, inspect the current page and navigation history without replay. The observed normal success route is emailmerge_responseatt_done.jsp; require the visible resume-upload success and recruiter-notified acknowledgement, correlated form_submit history, HTTP200 when exposed, and history's original userTypedURL matching the email link. Retain the original navigation timestamp. A shortened display name caused by URL-fragment formatting does not authorize repairing identifiers or resending.
7. If the native site exposes no downloadable uploaded PDF, record that limit. The browser-selected hash and normal upload success are distinct from an independently downloaded server copy. For the email channel, download the exact actual Sent attachment and hash it against the user's exact approved artifact, with matching sender/recipient/body/thread and no unintended CC/BCC.
8. Log both channel proofs, the exact approved PDF hash and approval receipt, actual form answers (or none beyond upload), one application credit, and owner/due date. Read Teal Applied/date/readable Notes back and close only the completed owned response tab. Never use a logging failure as grounds to replay an upload or email.
