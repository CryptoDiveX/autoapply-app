# Breezy application workflow

Use for official employer or recruiter Breezy forms after the normal VB Jobs canon, duplicate and cost gates.

1. Create the application tab through dedicated Cloak CDP with `background: true`. Save the exact observed posting and application URLs, body and full field metadata.
2. When a recruiter hosts the form, identify the named end employer in the official posting and run the rolling company guard on that end employer, not just the recruiting agency.
3. Upload the approved-format resume through the actual file input, commonly `#main-attachment`. Wait for the rendered `Attached` state and exact filename. Check the Angular candidate model has a resume URL, correct file_name and no error. Upload success alone is not application success.
4. Fill normal fields through native input/textarea value setters and bubbling input/change events. On Angular Breezy forms, use `angular.element(document.querySelector('[name=cName]')).scope().candidate` for read-only payload QA when available. Typical names are cName, cEmail, cPhoneNumber, cSummary and cCoverLetter. Inspect each live form instead of assuming these are universal.
5. Compare displayed field values and retained candidate values. Inspect hidden normalized location, salary and EEOC values for contradiction. An empty location object is not a false country when the form asks no location question; make Batumi current residence clear in the tailored cover text and Teal when using the approved Canada-first resume.
6. Filter validation nodes by actual rendered visibility before declaring a blocker. Breezy can keep every possible required-field error in hidden DOM elements even when the fields are valid. Save both the visible page text and retained values.
7. Keep Experience Summary separate from Cover Letter. Generate tailored copy through required Sonnet, then manually check named claims and unsupported universal qualifiers such as 'every release'. Do not transfer subscription experience from Apex Industrial into an invented current agency subscription offering.
8. Optional work-history and education repeaters may remain empty when the complete record is provided in the attached resume. Record that choice in Teal instead of claiming fields were filled. After resume parsing settles, inspect hidden candidate.summary, work_history and education too: the native parser can invent a revenue qualifier or assign one employer's history to another even when those fields have no visible controls. When the exact position application_form marks them hidden or optional, omit inaccurate auto-derived optional fields entirely rather than authoring replacement prose or modifying approved PDF bytes. Save before/after committed-state evidence and require the actual final application payload to omit those claims. Do not clear mandatory questions or legal controls.
9. Submit only after exact field, resume, contact, truthfulness, legal and duplicate QA. Save the immediate click result separately from the later external readback.
10. Require explicit rendered confirmation such as `Your application has been submitted successfully`, correlated with the normal native POST success and accepted payload. Some Breezy themes omit the `Application Submitted` heading, so do not require both literal strings when the explicit success sentence and native response are verified. A route ending in `/apply/submitted` alone is insufficient. If an overly strict heading check fails after success, recover only read-only confirmation and network verification, never resubmit. Save the page body and screenshot, then finish Teal Applied readback, canonical log and outreach database/CSV before counting. Correlate the native POST response by its requestId and method, not just its URL: Breezy can return HTTP200 to OPTIONS and HTTP204 No Content to the real application POST. Record the actual status, treat 204 as having no response body, and require the same guarded upload, committed resume reference, exact POST payload and normal-flow success page. Never resubmit because a read-only verifier initially expected HTTP200.
11. Preserve an already verified external confirmation when Cloak exits before Teal completion. Recover Teal through an authorized, provably background-safe session and finish the record. Do not resubmit a confirmed application merely because its tab disappeared.
12. Tolerate optional Markdown JSON fences from the copywriting provider even when response_format requests JSON, but never treat JSON parsing success as claim QA. Preserve rejected drafts for audit and redraft unsupported copy before use.
