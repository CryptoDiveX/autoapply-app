# Personio native applications

1. Read the live role and native form, then inspect the React ancestor's observed `formConfig`. Personio can render every input with native `required === false` while `formConfig.fields` and `documentCategories` correctly distinguish mandatory and optional fields. Do not infer optionality from the HTML property or force answers to optional unsupported questions.
2. Use native input focus/select and `Input.insertText`, including `select()` rather than `setSelectionRange()` on email inputs. Blur and compare the DOM values with the committed Final Form values. An observed React provider can expose its API directly as `memoizedProps.value.getState()`, not necessarily under `value.form`. Read `getState()` and `getRegisteredFields()` only, never call submit/change handlers to bypass the normal form.
3. Call the approved-file guard inside the actual file-selection/upload script immediately before `DOM.setFileInputFiles`, keeping DOM operations on one CDP session. The file input can become empty after a successful upload, so require the visible filename, normal `/api/v1/documents` response and committed `documents.cv` reference together. Save the actual returned UUID, filename and size; do not invent a storage URL or remote hash.
4. Before one normal visible Submit Application click, recheck exact candidate values, optional unselected fields, committed file UUID and absence of unsupported consent or challenge. Invoke the approved-file guard again inside the final-submit script. Record intent before click and never resubmit to repair evidence.
5. Save the normal native application request and response. Audit the observed final payload by mapping each `attributes` entry's exact `id` and `value`, the top-level `email`, and the `files` UUID/filename/category back to committed form state. Log human-readable question labels alongside native field IDs. Retain only candidate fields and correlation metadata in surfaced audit summaries, excluding sender/security/challenge envelopes. An HTTP200 response containing an empty JSON string is not success by itself. Require the normal-flow page stating the application was received and verify the exact job, contact values and uploaded UUID in the actual request payload. Preserve the native request timestamp independently of later recruiter emails. Private file bytes may not be downloadable; label that limitation without weakening the normal upload/reference/receipt chain.
6. Verify exact Teal Applied relationship, included status name, native application date, role, readable notes and answers before clean credit. A later recruiter email or invitation must not change the original native date or turn the channel into direct email.
7. When LinkedIn's live profile omits experience but public first-party extraction supplies it, keep the distinct source evidence. Do not attribute ownership of the vacancy merely from a recruiting title, use a former-employer email from an old post, or claim the live page displayed facts it omitted. Preserve exact public professional contact provenance and use recipient-specific Pending or Sent invitation proof.
