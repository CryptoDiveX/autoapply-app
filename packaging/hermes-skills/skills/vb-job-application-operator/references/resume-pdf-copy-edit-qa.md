# Resume PDF copy-edit QA

Use when a user requests tailored wording but requires the original approved visual resume format.

1. Keep the approved reference immutable. Draft candidate wording through scoped Sonnet and retain exact source-slot provenance. Preserve historical job titles and distinguish academic projects from professional experience.
2. Keep approval state in folders/manifests/guards, not employer-facing footers. Present a clean exact PDF for approval; later byte changes must not silently inherit approval.
3. Test actual PDF order with an ordinary unsorted parser, not only spatial extraction. Redaction plus appended text can render perfectly while the headline, summary, education and skills extract at the bottom. Sorted extraction alone does not prove logical order.
4. Repair the PDF itself. Prefer the verified editable template. A native-text-fragment repair must retain original fonts/glyphs and graphics-state dependencies, sort real text objects by position, and suppress replayed position operators from state-only prefixes to avoid phantom whitespace. Explicitly reject unsupported operators rather than generalizing a tested path to every PDF.
5. Re-render both pages after every stream/footer edit. Compare all glyph coordinates/fonts and rasters. Report measured differences; a one-level antialias variation is not zero pixel difference. Reject shifted text, missing resources, changed photos/links, clipping, overlap, unrelated layout changes and new underfill.
6. Check normal-parser order: name, heading/contact, Summary/body, experience; then proper education and skill-label/description pairs. Verify model copy verbatim, frozen lines, links, strict PDF parsing, and absence of internal labels or markup artifacts.
7. Show the final PDF, outbound message and material location/authorization facts for approval. Do not alter the generic frozen fingerprint during review or call a draft approved because worker QA passed. Retain its separate hash until exact user approval permits a narrowly scoped outbound exception.
8. After actual exact-artifact approval, the guard supports `approved_resume_guard.py <exact-file> --approval-receipt <receipt.json> --target <exact-recipient-or-original-application-url>`. Preserve the default generic frozen fingerprint. Record explicit human approval provenance, exact resolved file path/hash and finite exact allowed targets in the receipt. Test the generic regression, approved recipient/link, wrong target, wrong bytes/path and missing scope without sending. Use subprocess.run(..., check=True) inside every actual send/upload path and retain its receipt. This proves document/target scope only, not permission for another message, role, recipient or duplicate submission.
