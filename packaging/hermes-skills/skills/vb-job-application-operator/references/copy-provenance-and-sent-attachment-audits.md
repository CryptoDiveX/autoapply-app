# Immutable candidate copy and exact Sent attachment audits

## Candidate-copy provenance

Keep copywriting fact whitelists in normally spaced prose with exact canonical employer names. Joined employer names and run-together constraints can introduce misspellings and narrative drift. Request separate complete project, motivation, logistics and signature values when modular QA helps. If only one paragraph fails claim or no-gap QA, request a new immutable replacement for that paragraph alone, then compose whole safe model paragraphs and revalidate every required answer. Do not rewrite candidate prose or regenerate already valid fields.

Save every Sonnet request, raw response and parsed draft under a distinct immutable revision filename before requesting another draft. When composing approved text from more than one model response, record the exact reused spans and their source files. Never overwrite the only response proving candidate prose provenance, and never claim operator-authored repairs were model-written. Recover existing provenance from actual session tool output if needed; do not regenerate or resend merely to create historical proof. If a complete otherwise valid draft exceeds the length cap, an optional whole model-authored paragraph may be omitted without rewriting candidate prose. Save the exact selected paragraph indices/spans, immutable source, omission reason and final body; recheck the resulting word count, every required answer, motivation, logistics, signature and sentence completeness before sending. Never omit required screening content or splice fragments merely to satisfy length.

## Employer geography versus candidate working hours

Treat employer wording such as work from anywhere or any timezone as the employer's geographic scope, not evidence that Alex can work every timezone or full US hours. Keep candidate availability within canon. If a draft adds unlimited-hours availability, preserve it as rejected and replace only the complete logistics paragraph through Sonnet, then recheck final length and exact source spans before sending.

## Double-escaped model paragraph separators

When a complete model JSON string contains literal backslash-n paragraph separators, retain the immutable raw and parsed responses and normalize only the known candidate-text field's paragraph separators to real linefeeds. Do not run a general escape decoder over URLs, paths or arbitrary values. Save this serialization-only transform explicitly, preserve every candidate word and exact source paragraph boundary, then repeat claim, contact, location, length and sentence QA. Before outbound, reconstruct the selected body from its recorded immutable source paragraphs using that same normalizer and assert exact equality. Composition may omit whole unsupported or unnecessary model paragraphs or select a complete safe paragraph from another retained revision, but never rewrite candidate prose or resend solely for serialization/provenance evidence.

## Audit artifact namespaces

Before executing an adapted helper, inspect its imported module namespace and run a nonsending dependency/save-path probe. A wrapper can expose its artifact writer as `o.save` rather than `save`; resolve that alias before candidate action, and recover only the read-only audit if the mismatch is discovered after sending. Reserve distinct immutable filenames for preparation, first post-send and final delivery checks before executing an adapted helper. Assert every planned output path, not only the top-level receipt, because an earlier preparation can already own a similarly named failure-search file. If a later read-only check collides after Sent/attachment verification succeeded, preserve the completed receipts and run only that unfinished check under a new name; never replay the sender or attachment download merely to rebuild the combined audit.

## Tracker summary contact binding

Build tracker summary recipients from the exact saved send intent, not company-name substitutions in an earlier target helper. A replacement company token can silently invent an email domain while the actual sender remains correct. Compare every tracker summary address with actual Sent headers before ledger credit. If only Notes are wrong, preserve the real Sent and attachment proof, correct the exact Notes and read back status, original provider date and rendered paragraphs. Never resend the application to repair tracker-only attribution.

## Opaque Gmail attachment IDs

Do not require opaque attachmentId values to equal earlier readbacks of the same exact Sent message. They can change while the attachment remains identical. Require the exact provider message ID, sender, recipients, subject, body, attachment count, filename, MIME type and size to match. Normalize CRLF to LF only for candidate-text comparisons while preserving original retained responses. Download using the current observed attachmentId and hash those received bytes against the frozen approved fingerprint. A saved local attachment or unchanged filename alone does not prove the current received bytes.

Preserve a failed whole-object equality check and recover only the read-only audit under a new immutable prefix. Reuse already-fetched current exact readbacks when appropriate; allocate new filenames for missing retrievals and actual downloads. Never resend, reupload, rewrite Teal or label a document incident solely because an opaque attachment ID changed. Correlate new NDRs by the original RFC Message-ID as usual.
