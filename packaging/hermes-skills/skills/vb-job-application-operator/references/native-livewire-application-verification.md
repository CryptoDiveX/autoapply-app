# Native Livewire application verification

1. Inspect the rendered form's wire:submit and wire:model attributes read-only. Match its exact component name. A sendCode step precedes a separate submit action, so a code-request response is not application receipt. Never call hidden methods or manufacture requests.
2. Inspect the currently loaded public upload implementation. If direct HTTP is blocked while the script loaded normally in Cloak, retrieve that exact observed script with ordinary page-context fetch and preserve its real response. The framework's _startUpload, FormData and _finishUpload path establishes implementation only, not actual upload success.
3. Invoke the approved-file guard inside the actual upload script immediately before DOM file selection. Hash the browser's selected File, compare size/name/frozen hash, and correlate the normal upload response with the committed resume reference on that component. Guard again inside the final-submit script immediately before its normal Submit click.
4. Whitelist candidate fields, resume reference, phase, submitted flag, native method names, response status and sanitized confirmation text. Exclude full snapshots, checksums, security tokens, cookies, signed URL queries and verification-code values. Keep file-binding parameters only, never arbitrary call parameters. Derive sanitized network evidence in memory and flush partial results in finally.
5. Use only a clearly matching current application-verification code under existing authorization. Verify exact employer sender, recipient, application purpose and request timing. Never retain or print raw codes or code-bearing MIME bodies. Account-login, assessment, legal and permission gates remain separate stop conditions.
6. Require the one normal final submit request with its committed resume reference, correlated successful response reporting submitted true, and visible Application received reached through that action. Preserve the native request time separately from later recruiting mail. Label unavailable multipart binary and private remote bytes explicitly. Never claim a downloaded hash or resubmit for better evidence.
7. Verify exact Teal selected status, date, Notes and rendered paragraphs before credit. Decode documented HTML entities only for comparison with original prose. Serialization-only audit mismatch requires a read-only verifier repair, not another tracker write, upload or submit. Distinguish general intake from a named vacancy and later general-inquiries email from the native application channel.
