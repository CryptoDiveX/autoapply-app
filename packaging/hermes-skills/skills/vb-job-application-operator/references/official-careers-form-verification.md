# Official careers intake and Teal Notes verification

1. Treat an employer's general Send CV intake as general intake, not a native job-specific ATS route. Keep the exact live role title and original posting URL in source and cover fields, and state the actual channel in Teal and the application log. Never infer the role is open from a generic intake page alone.
2. For Contact Form 7, submit through the observed live form using normal browser interaction. Verify the visible receipt plus `wpcf7mailsent`, `mail_sent`, form status `sent` and absence of validation errors. Hidden or pre-rendered thank-you text before submitting is not proof. For a custom WordPress/AJAX careers form, enable Network observation before the native submit, save the exact visible fields and FormData including selected filename/size, and capture the actual application response request ID, URL, HTTP status and body. Require explicit application success in that response and the receipt reached by the normal redirect; HTTP 200 or a separately reachable thank-you page alone is insufficient. Retain the in-upload and immediate pre-submit approved-file guard receipts and actual submit timestamp. Later reconciliation should inspect this captured chain and fetch the exact current Teal record without replaying the form; distinguish saved external submission proof from fresh Teal readback in the audit.
3. If a JavaScript `.click()` returns without revealing the intake form, wait for page scripts, inspect the actual button, scroll it into view and use background CDP Input mouse events. Do not force hidden fields visible or submit via a guessed endpoint.
4. Keep invisible browser-native risk assessment distinct from a visible challenge. Do not outsource or bypass a visible CAPTCHA.
5. Inspect Teal's actual Notes editor after API writes. Plain newline text can survive API readback yet render as one collapsed Tiptap paragraph. When that happens, select content within the exact record's editor and rewrite using `Input.insertText` per line and actual Enter key events, then blur and wait for autosave.
6. Read the exact Teal record again after editor repair. Verify Applied status, applied_at and follow-up date remain intact. Compare source lines to editor paragraph text. Do not require a multiline email body to appear as a literal substring of the editor's whole innerText: separate paragraphs can introduce additional blank lines. Preserve exact candidate strings in raw API/Sent proof, verify each nonempty source paragraph against the observed paragraph sequence, and use whitespace normalization only for the rendered UI comparison. A rendering-only mismatch calls for read-only verification recovery, not another email send or unnecessary tracker rewrite. Tiptap's UI-only `<br class="ProseMirror-trailingBreak">` can persist as `<br/>`; normalize only that known serialization difference, never the candidate answer content.
7. Preformat API-only notes as escaped HTML paragraphs with blank paragraphs between headings and bullets, then read back the exact value. Preserve existing Applied records when updating any archived triage rows.
8. Compare Gmail Sent bodies after normalizing CRLF to LF. A transport newline difference is not a content mismatch and must not trigger a resend. Persist the message ID before readback so retries verify the existing message rather than sending a duplicate.
9. Set Teal's exact `role` attribute, not `job_title`, and include `job_description` and `follow_up_at` explicitly. The API can return success while silently ignoring an unknown field, leaving the visible card labeled `No role or position`; verify the exact role in server readback and the UI before counting.
10. Use Teal's observed singular `note` attribute for Notes, not a guessed `notes` field. An ignored field can return a successful create while leaving Notes null. If a create has already succeeded, recover its exact ID from the saved receipt, update only that record and read back its actual `note` plus rendered paragraphs; never create another record to repair Notes.

10a. Normalize browser-generated ATS submit timestamps to whole UTC seconds before Teal writes. Teal persists `applied_at` at second precision, so millisecond strings can fail exact comparisons even after a successful write. Inspect the saved exact record before repairing only the timestamp representation, and never repeat the external application to repair logging.
11. Preserve unsolicited CDP Network events while awaiting command responses. A synchronous RPC helper that discards nonmatching messages can lose the actual submit request or response during Runtime.evaluate; buffer those events or run a dedicated event reader before the first native submit. If observation is incomplete after a real send, recover read-only from the original form's provider response events, resource timing and visible receipt, describe the missing network detail accurately, and never replay the application for cleaner instrumentation.
12. For native Gravity Forms careers applications, inspect the exact role-page form ID, labels and field containers before filling. A field labeled LinkedIn can be an invisible honeypot whose description explicitly says leave unchanged; fill only the visible actual LinkedIn field. Multi-file upload widgets can clear the file input after uploading, so verify the approved original filename, temporary storage reference in `gform_uploaded_files`, and completed preview rather than requiring a nonempty file input. Keep the immediate approved-file guard inside the actual DOM upload path. Submit once through the observed button with Network observation and a `gform_confirmation_loaded` listener enabled first. Require the exact role-page POST response, matching form ID, newly rendered confirmation wrapper and form replacement together; a generic thanks message or HTTP200 alone is insufficient. Preserve native request time separately from any later email follow-up. The synchronous CDP RPC helper may discard early Network events, so buffer unsolicited events when exact capture is required and never replay a successful application for cleaner traces.
For employer careers boards whose whole role card is a mailto anchor, inspect the exact card text and observed href together in the live DOM. A general careers page can contain several role-specific subjects to one inbox; select only the intended role's published recipient and subject, preserve the full role and remote policy, and record the actual channel as employer-prescribed direct email, not ATS. Complete normal approved-file, exact Sent attachment, duplicate, country and Teal gates. Keep retrieval scripts distinct from standard-library module names such as inspect.py, because that filename can shadow Python dependencies before the preflight runs.

14. On Kadence WordPress careers pages with multiple role modals, bind the observed Apply control's data-modal-open value to the exact visible modal and its retained _kb_form_id before candidate entry. Global checkbox IDs and field names can repeat across hidden role forms, so scope selectors and final FormData to that modal. Buffer Network events before one normal Submit and require the matching admin-ajax.php POST, HTTP200 JSON success:true and newly rendered kadence-blocks-form-success message together. A native no-file intake can be a legitimate application, but receives no delivered-approved-PDF checkpoint credit; retain its actual Date applied and include it in the thirty-day employer duplicate guard independently of strict campaign counting. Do not email an unsolicited resume or repeat the form to create file evidence.

15. On Elementor careers forms, inspect the exact observed lazy `form.*.bundle.min.js` from the live page's resource inventory when the main elements-handlers bundle lacks submission logic. Read the normal handler's `new FormData(form)`, AJAX action and success/error branches before candidate entry; a main-bundle miss alone does not establish a nontransmitting form. If direct public script retrieval fails while the employer page works, fetch that same observed script read-only in the existing same-origin browser context. Scope fields and Submit to the exact careers form, because newsletter controls can repeat email IDs. For deferred multipart uploads, guard file selection and again immediately inside the actual Submit script, retain the committed browser File hash, buffer Network events, parse candidate parts using the body's boundary when Content-Type is omitted, and require the exact successful response plus newly rendered receipt. Record omitted binary/private remote bytes explicitly. A successful Elementor handler resets fields and the role dropdown to defaults, so verify the saved pre-submit state and actual multipart role/file binding rather than refilling or submitting again.

13. On a custom Angular careers modal, scope all reads and field changes to the visible vacancy form, not a hidden general-contact form elsewhere on the page. Read Angular valid/invalid classes and visible errors because native `required` flags can be absent. If a subject permits letters only, remove punctuation and normalize spaces from the already approved model draft, preserve the original and exact transformed text, and recheck normal validation without adding candidate prose. Verify actual serialized FormData, including vacancy/course ID, contact values and selected attachment metadata, as well as the normal response and newly reached success dialog. A fail-closed outgoing-payload observer may add QA checks but must not modify employer payloads, change validation or bypass legal/security fields.
